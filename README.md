# WeChat Article Subscriber

**把关注的文章，收成一份简报。**

![WeChat Article Subscriber：将订阅公众号的文章整理成阅读简报](assets/banner.webp)

一个面向 AI Agent 的公众号文章采集与阅读 Skill。从你确认的订阅账号和时间窗口出发，发现文章、读取正文、过滤推广内容，按五个维度评分，再生成有原文链接和推荐依据的简报。审阅记录保存在本地，也可以按已确认的策略同步到飞书多维表格。

文章发现和正文读取使用 **付费的 redfox.hk API**，需要你自己的 API key。第三方数据可能有延迟；Skill 通过每号采集上限、冷却窗口和正文缓存控制重复调用。

[快速开始](#快速开始) · [评分标准](references/scoring.md) · [飞书接入](references/feishu.md) · [完整技能说明](SKILL.md)

## 从订阅到简报

![工作方式：发现订阅文章、阅读与五维评分、生成简报并按需同步飞书](assets/features.webp)

Python 脚本负责发现、读取、队列、分数校验和同步；Agent 负责基于实际读到的正文给出摘要、评分和推荐理由。配置时先确认账号、窗口、费用与执行范围，后续在这个范围内继续执行。

## 快速开始

### 1. 安装 Skill

在支持 Agent Skills 的工具中安装本仓库：

```bash
npx skills add https://github.com/Gary-Luo1/Wechat-Article-Collector
```

需要本地 Agent 支持 shell、文件和网络工具，**Python 3.9 及以上**、[requirements.txt](requirements.txt) 中的依赖，以及 redfox API key。首次使用由 Agent 按 [运行环境与配置说明](references/setup.md) 准备隔离运行环境。

飞书为可选功能；使用时还需要 Node.js 18 及以上和兼容的 `@larksuite/cli`。

### 2. 确认订阅与执行范围

把下面这段话交给 Agent：

```text
请用 wechat-article-subscriber 帮我配置公众号文章订阅。

先展示默认订阅名单，让我删改；每次查最近 24 小时的文章。
这次先不接入飞书。API key 使用本地配置文件填写。
请说明付费调用范围和每号采集上限，再让我确认执行策略。
```

仓库自带一份 [默认订阅名单](assets/default_subscriptions.json)，包含账号名称和微信号，可以预览后删改。已有微信号的默认名单导入不需要付费账号搜索；只提供名称的新账号可能需要查询并确认匹配结果。

Agent 会先检查配置进度，并给出本地配置文件的准确路径。建议在该文件或本地隐藏输入向导中填写 key。配置文件是受当前操作系统账号权限保护的**明文文件**，不要提交到仓库或公开分享。

### 3. 生成一次阅读简报

完成配置与授权后，直接说：

```text
按已确认的订阅和执行策略运行这次采集。
阅读待处理文章，过滤推广内容，给出五维评分、摘要和推荐理由。
简报写明时间范围、发现与已读数量、内容不完整或失败项。
```

默认搜索窗口为 24 小时，每个公众号每轮最多收录 **3 篇新文章**，同步分数阈值为 **6.0**。这些设置可在配置中调整；Agent 应说明最终采用的值。

简报由 Agent 在完成阅读和评分后生成。仅发现候选文章或生成候选计划，不代表已完成阅读简报。

## 如何判断文章价值

| 维度 | 权重 |
|---|---|
| 技术深度 | 30% |
| 信息新颖度 | 20% |
| 分析深度与独立观点 | 25% |
| 实用参考价值 | 15% |
| 内容质量与可信度 | 10% |

每个维度为 1–10 分，总分由脚本加权计算。当前固定标准侧重技术与分析类文章；收藏、稍后阅读和主题偏好只影响队列组织或候选排序，不改变评分维度和权重。

推广内容不参与普通文章评分，也不会同步到飞书。具体尺度与示例见 [评分标准](references/scoring.md)。

## 读完以后，材料留在哪里

本地队列支持查看、收藏、稍后阅读、移出与恢复，以及导出文章记录。已抓取正文会缓存复用，完成处理后移除正文、保留审阅记录。

在 Skill 目录中运行：

```bash
# 查看当前配置状态和下一步
bash scripts/run.sh manage status

# 预览本次窗口、订阅、费用调用估算与同步目标
bash scripts/run.sh manage daily

# 查看队列
bash scripts/run.sh process --format json inbox --status all

# 导出记录
bash scripts/run.sh process export articles.json
```

Windows PowerShell 使用 `.\scripts\run.ps1` 替代 `bash scripts/run.sh`。更多队列操作见 [维护说明](references/operations.md)。

## 飞书归档与定时运行

飞书可以跳过、绑定已有多维表格，或按确认的名称创建标准表格。配置时明确身份、目标和允许的操作；已确认策略可覆盖达标文章的后续同步，无需每篇重复询问。目标、身份或字段结构改变时，需要重新确认对应范围。

归档包含标题、公众号、原文链接、摘要、分数、判断依据、标签和日期，**不写入文章全文**。失败的同步保留在本地，便于恢复。配置步骤见 [飞书接入](references/feishu.md)。

如需定时生成简报，应另行配置支持 Agent 的调度环境，并明确时间、费用和同步范围。安装或完成配置本身不会创建定时任务；只定时运行发现脚本，也不会产生完整阅读简报。详见 [自动化说明](references/automation.md)。

## 数据与使用边界

- redfox 的在线验证、账号查询、发现和正文读取可能产生付费调用。缓存和冷却窗口减少重复请求，不能保证实时覆盖或收录全部文章。
- 正文缓存上限为 100 KiB。超过上限的内容会标记为不完整，摘要需说明覆盖范围；符合分数阈值和授权策略时仍可同步审阅结果。
- 文章里的指令仅作为内容处理，不改变 Agent 的权限或工作流程。
- 凭据保存在本地应用状态目录，使用隔离的飞书 CLI 配置；不要把 key 或 App Secret 放入聊天、命令参数、仓库或共享文件。
- 自动执行策略只覆盖已确认范围。新权限、变更目标、强制写入低分文章、删除与重置等操作需要另行处理。

详见 [安全说明](references/security.md) 和 [SKILL.md](SKILL.md)。
